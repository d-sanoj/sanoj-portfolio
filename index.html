FinAgent

A conversational finance assistant that turns everyday banking activity into clear, private, plain-language insight.

Objective

The objective of FinAgent is to create a private AI-powered personal finance assistant that lets users ask questions about bank accounts, spending, balances, income, and transactions in plain English through Telegram.

It connects to bank data using SimpleFin and uses an LLM backend such as Ollama for local/private inference or Groq for faster cloud-based responses. The main goal is to make personal finance tracking easier, faster, and more conversational without needing to open multiple banking apps.

Process

The project was built around a two-phase AI workflow. First, the user asks a natural-language financial question, such as "How much did I spend on Amazon this year?" The LLM does not directly calculate the answer; instead, it extracts the user's intent into structured JSON, including the type of query, merchant or category, and date range.

Then deterministic Python code uses Pandas to run the actual calculations on the transaction data. This makes the system more reliable because the LLM handles language understanding, while tested Python logic handles financial computation.

Financial data is pulled from SimpleFin, saved locally as Parquet files, and loaded into the chatbot engine for analysis. The project includes separate modules for syncing data, loading transactions, running the chat engine, and handling Telegram/WhatsApp bot interactions.

Tools
Python Telegram Bot API SimpleFin API Ollama Groq Pandas PyArrow Parquet Flask Requests python-telegram-bot python-dotenv Raspberry Pi Databricks Azure data lake pyspark Antigravity
Value Proposition

FinAgent creates value by turning personal finance analysis into a simple chat experience. Instead of manually checking multiple bank apps or spreadsheets, users can ask questions like "What are my top spending categories this year?" or "How much did I spend on Netflix in the last 3 months?" and receive quick answers based on real transaction data.

It also improves privacy and control. With Ollama, financial data and questions can run fully locally, meaning sensitive information does not need to leave the user's machine. Even when using Groq, transaction data remains local and only the question text is sent for processing. The bot is also owner-locked so only an approved Telegram user ID can access it.

Overall, the project provides a practical, privacy-focused AI assistant for personal finance management. It saves time, reduces the effort needed to analyze spending, gives faster access to financial insights, and demonstrates how LLMs can be combined with deterministic data processing to create reliable real-world applications.

Web / History

Turing > Today

A guided AI-history experience that makes technical milestones easier to scan, understand, and connect to modern AI systems.

Objective

The objective of Turing > Today is to present the complete history of artificial intelligence as a clean, visual, scrollable timeline. It explains AI as a long evolution, starting from Alan Turing, early computation, neural ideas, and the Dartmouth Conference, then moving through symbolic AI, expert systems, AI Winters, machine learning, deep learning, transformers, generative AI, frontier models, AI agents, and AI regulation.

Process

The project was created by researching key milestones in AI history and organizing them into a chronological timeline. The website was then built using HTML, CSS, and JavaScript, where data.js stores the timeline content and script.js dynamically displays the cards, people, companies, references, and popups. CSS was used to make the design clean, responsive, and easy to navigate on both desktop and mobile.

Tools
HTML CSS JavaScript GitHub GitHub Pages .nojekyll browser DOM APIs CSS media queries OpenAI Codex
Value Proposition

Turing > Today creates value by making AI history easier to understand through a visual, chronological experience instead of a long plain-text article. It helps users see how AI developed step by step, from early theory and symbolic systems to modern foundation models, GPUs, cloud infrastructure, multimodal systems, reasoning models, AI agents, and regulation.

It is also useful as an educational portfolio project because it combines historical research, source-backed content, interactive web design, responsive layout, and storytelling. The project highlights major researchers, builders, labs, and companies such as Alan Turing, John McCarthy, Geoffrey Hinton, Yann LeCun, Fei-Fei Li, OpenAI, Anthropic, Google DeepMind, NVIDIA, Microsoft, Meta, IBM, Hugging Face, DeepSeek, and the European Union.

Machine Learning / Deep Learning

Machine Learning vs. Deep Learning

A comparative study that matches model complexity to the structure of the problem, from seller-churn prediction to contextual analysis of Latin inscriptions.

Objective

This assignment examines when traditional machine learning and deep learning are each the better fit for a real-world problem. It compares their data requirements, interpretability, computational cost, and ability to capture complex relationships, using examples drawn from professional and academic experience.

Process

The assignment was developed by selecting two real-world problems from professional and academic experience, then analyzing which class of model best fits each problem's data structure, interpretability requirements, and computational constraints. The ML case study drew on operational data patterns from e-commerce seller management, while the DL case study extended an existing research project on Roman inscriptions, applying Transformer-based NLP to unstructured Latin text.

Tools
Microsoft Word Python Scikit-learn Transformers Support Vector Machines NLP Pandas
Machine-Learning Case Study

The first case study proposes a Support Vector Machine to identify third-party retail sellers at risk of becoming inactive. Structured indicators such as sales volume, active listings, inventory, support contacts, account health, and prior inactivity would allow the model to flag risk earlier and help account managers prioritize targeted support.

An SVM offers a practical balance of nonlinear pattern recognition and manageable complexity for this structured classification problem. The study also evaluates logistic regression, decision trees, random forests, k-nearest neighbors, and Naive Bayes as alternatives.

Deep-Learning Case Study

The second case study extends an urban-scaling project based on Latin inscriptions from the Epigraphik-Datenbank Clauss/Slaby. A Transformer-based NLP system could support translation, semantic search, abbreviation expansion, text reconstruction, named-entity extraction, and thematic analysis.

Contextual representations would let researchers study not only how many inscriptions are associated with Roman cities, but also how their language, topics, occupations, civic roles, and religious or military themes vary across geography, time, and urban scale.

Value Proposition

The strongest model is not automatically the most complex one. Traditional machine learning is often more efficient and explainable for prepared, structured features, while deep learning is better suited to unstructured language where meaning depends on context and sequence.

Both applications require responsible human oversight: churn scores should remain risk indicators rather than final decisions, and generated translations or historical interpretations should be validated by subject-matter experts.

Machine Learning / AI Coaching

ML Training Methods

A collaborative dialogue with an AI coach to explore how machines actually learn, from labeled data to reward signals, and why each approach matters.

Objective

This activity was designed as an interactive, dialogue-driven exploration of the core training methods used in machine learning. Rather than reading a textbook or watching a lecture, I engaged directly with a pre-trained AI chatbot (the Machine Learning Training Methods Coach on SchoolAI) to work through a set of guided questions covering supervised learning, unsupervised learning, reinforcement learning, optimization algorithms, and the general pipeline for training models.

The goal was not just to answer questions correctly, but to reason through each concept collaboratively, using the chatbot as both a tutor and a thinking partner.

Process

I joined the SchoolAI Space using the instructor-provided link and began a structured conversation with the chatbot. The bot guided me through seven core questions, one at a time, prompting me with follow-up hints, asking me to clarify my reasoning, and providing feedback when I was on the right track or needed to reconsider.

The experience felt less like a quiz and more like a peer tutoring session. The chatbot adapted to my responses, digging deeper when I gave a surface-level answer and confirming when I demonstrated genuine understanding. This two-way interaction was valuable because it forced me to articulate my thinking rather than passively consume information.

Guided Questions

The chatbot walked me through these topics during our conversation:

Supervised learning — I discussed how models learn from labeled training data by mapping inputs to known outputs, adjusting weights through loss minimization until predictions align with ground truth.

Unsupervised learning — I explored how models find hidden structure in unlabeled data through techniques like clustering (k-means, DBSCAN) and dimensionality reduction (PCA, autoencoders), where the goal is pattern discovery rather than prediction.

Reinforcement learning — I walked through how an agent learns optimal actions by interacting with an environment, receiving rewards or penalties, and updating its policy to maximize cumulative reward over time.

Role of algorithms — I reflected on why the choice of algorithm matters: it determines how the model searches the solution space, how fast it converges, how well it generalizes, and whether it can handle the structure of the data.

Training pipeline — I outlined the general steps: data collection and cleaning, feature engineering, model selection, training with a loss function and optimizer, validation, hyperparameter tuning, and evaluation on held-out test data.

Iterating over data — I discussed how multiple passes (epochs) through the training data allow the model to refine its parameters incrementally, reducing error with each iteration through gradient-based optimization.

Role of data — I explained how training data is the foundation of everything: its quality, quantity, diversity, and representativeness directly determine what the model can learn and how well it generalizes to unseen inputs.

Tools
SchoolAI AI Chatbot Brightspace
What I Learned

Working through these questions in a conversational format reinforced my understanding in ways that static reading does not. When the chatbot pushed back on an incomplete answer or asked me to connect a concept to a real-world scenario, I had to think more carefully about the "why" behind each training method, not just the "what."

I also gained a clearer mental model of how supervised, unsupervised, and reinforcement learning relate to each other: they represent fundamentally different assumptions about what information is available during training (labels, no labels, or delayed reward signals), and each unlocks a different class of problems.

Reflection

This was one of the more effective learning activities I have experienced in a course. The AI-guided format removed the pressure of being judged for wrong answers while still demanding rigor. The chatbot's hints were well-calibrated: specific enough to be useful, but open-ended enough that I still had to do the reasoning myself.

It also highlighted something I think is underappreciated in AI education: the ability to explain a concept clearly to an AI (or anyone) is itself a test of understanding. If I could not articulate why iterating over data helps, the chatbot would keep probing until I could. That loop of explain → get feedback → refine is exactly how deep learning works on concepts, not just parameters.

Value Proposition

Machine learning training is not a single technique but a family of approaches shaped by what information is available and what outcome is desired. Supervised learning needs labels, unsupervised learning finds structure without them, and reinforcement learning discovers strategy through trial and error. The shared thread is iterative optimization: every method improves by repeatedly adjusting its internal representation based on feedback, whether that feedback is a loss gradient, a cluster assignment, or a reward signal.

Engaging with an AI coach to work through these ideas was a practical reminder that understanding emerges from dialogue: asking questions, testing assumptions, and refining mental models through structured back-and-forth.

AI Leadership / Change Management

Navigating Human Bias

A leadership reflection on recognizing, addressing, and mitigating human bias in business, technology, and AI-driven decision-making.

Objective

This discussion explores how human cognitive biases influence AI systems, team dynamics, and organizational decision-making. The assignment asked leaders to craft a personal value statement on navigating human bias and develop field-specific strategies for addressing it, drawing on real-world examples from education, healthcare, and technology.

The learning objectives center on articulating the factors that contribute to successful change leadership in the context of AI/ML integration, and discussing how to navigate human bias in change management and leadership.

Personal Value Statement

As a future leader in business and technology, I believe that recognizing and addressing human bias is essential for building trust, encouraging innovation, and making ethical decisions. Human bias can influence hiring, team collaboration, customer interactions, and the development of AI systems.

My personal value is to lead with fairness, transparency, and accountability while creating an environment where diverse perspectives are respected and considered. I believe that effective leadership is not about eliminating bias entirely, which is impossible, but about being aware of it and taking intentional steps to reduce its impact on decision-making.

Strategy 1: Continuous Education on Cognitive Bias and Ethical AI

Regular workshops and discussions can help employees recognize common biases, such as confirmation bias and unconscious stereotypes, and understand how these biases can affect workplace decisions and AI outcomes. Developing this awareness encourages more thoughtful and objective decision-making throughout the organization.

Strategy 2: Prioritize Diversity and Inclusion

Diverse teams bring different experiences and viewpoints, making it more likely that hidden assumptions and biases will be identified before they become larger problems. This approach also improves creativity, collaboration, and the quality of AI systems by ensuring that products and services better reflect the needs of a diverse customer base.

Strategy 3: Regular Bias Audits for AI Models and Business Processes

AI systems should be evaluated using diverse datasets and fairness metrics to identify potential discrimination or unequal outcomes. Human oversight should remain an essential part of AI-driven decision-making, especially in areas involving hiring, customer service, or performance evaluations. Transparency about how AI systems make recommendations also helps build trust among employees and customers.

Strategy 4: Open Communication and Continuous Feedback

Employees should feel comfortable raising concerns about bias without fear of retaliation. Leaders should actively listen, encourage constructive conversations, and use feedback to improve both organizational practices and AI systems. This creates a culture of learning, accountability, and continuous improvement.

Tools
ChatGPT Brightspace
Value Proposition

Navigating human bias is not a one-time effort but a continuous practice. AI systems learn from data that humans provide, and if that data contains biases, the AI can pick up and repeat them through data selection, labeling, algorithm design, testing, and interpretation of results. Even though AI seems neutral, it can reflect and amplify human biases if teams are not careful.

Successful change leadership in the context of AI/ML integration requires leaders who understand that cognitive biases are invisible but influential forces. By promoting awareness, building diverse teams, implementing bias audits, and fostering open communication, leaders can create more equitable, trustworthy, and effective organizations and AI systems.
